# Архитектура oldbox

```
                 +----------------------+
                 |  SDL3 frontend       |
                 |  window / audio / in |
                 +----------+-----------+
                            | VideoFrame, key/mouse
                 +----------v-----------+
                 |  Machine             |
                 |  clock, wiring, POST |
                 +--+----+----+----+----+
                    |    |    |    |
          +---------+    |    |    +----------------+
          |              |    |                     |
   +------v------+  +----v----+  +-----v------+  +---v--------+
   | Cpu         |  | Bus     |  | PciBus     |  | Devices    |
   | IA-32 core  |  | RAM/ROM |  | BAR/config |  | S3, Voodoo |
   | x87 / MMX   |  | I/O map |  | routing    |  | AWE64, ATA |
   +------+------+  +----+----+  +-----+------+  +---+--------+
          |              |             |             |
          +--------------+-------------+-------------+
                     memory / I/O accesses
```

## Слои

- `src/core` (`bus.cpp`, `pci.cpp`, `common.cpp`) — адресное пространство,
  регионы RAM/ROM/MMIO, 64K I/O-карта, PCI-конфигурация и BAR.
- `src/cpu/` — интерпретатор IA-32:
  - `cpu.cpp` — декодер 1-байтовых опкодов, ModRM/SIB, сегментация,
    прерывания, строковые операции;
  - `cpu_0f.cpp` — двухбайтовые опкоды, CPUID, MSR-доступы, CMOV, MMX;
  - `cpu_system.cpp` — MSR, LDT/TR, TSS switch;
  - `cpu_x87.cpp` — x87 FPU;
- `src/chipset/` — i440BX/PIIX4, PIC, PIT, RTC, DMA, 8042, SMBus.
- `src/cpu/apic.cpp` — локальный APIC Pentium II (это блок процессора,
  не чипсета).
- `src/video/` — S3 Trio64 (VGA + 2D engine) и Voodoo SST-1 (FBI/TMU).
- `src/audio/` — SB16 DSP, CT1745 mixer (включая CD-вход от привода),
  MPU-401, EMU8000, YMF262/OPL3 FM (`opl3.cpp`).
- `src/storage/` — PIIX4 IDE/ATA/ATAPI (ISO и BIN/CUE с CD-DA) и 82077AA FDC.
- `src/machine.cpp` — сборка машины, карта памяти, запуск, reset, POST-коды.
- `src/perf.cpp` — счётчики производительности: хостовое время по узлам,
  история кадров, отчёт для консоли и панели F3 ([docs/perf.md](perf.md)).
- `src/console.cpp` — консоль команд (CLI): разбор строки, команды смены
  носителей, пауза/шаг, `key`/`type`, скриншоты. Панель F2 и необязательный
  ввод из stdin живут в `src/frontend/sdl3.cpp`; команды выполняются в главном
  потоке между кадрами.
- `src/bios/fallback_bios.S` — настоящий 16-bit POST ROM, собираемый `as`/`ld`
  и встраиваемый в бинарник.

## Поток одного кадра

1. `SdlFrontend` опрашивает SDL-события, передаёт клавиши/мышь в `Machine`.
   Строки, набранные в консоли (F2 или stdin), выполняются здесь же — между
   кадрами, в главном потоке.
2. `Machine::run_frame()` выполняет CPU до бюджета 1/60 эмулируемой секунды.
3. Каждые ~512 циклов вызываются `tick()` чипсета, видео, ATA, FDC, audio.
4. `S3Trio64::tick`/`Voodoo::tick` при необходимости перерисовывают кадр.
5. `Machine::display_frame()` выбирает источник: Voodoo, если он не в
   passthrough и уже сделал swap, иначе S3.
6. `SdlFrontend` загружает XRGB8888-пиксели в SDL-текстуру и презентует.

## Профилирование

Каждый батч устройств (`Machine::tick_devices`) и каждая тяжёлая операция
модели (кадр S3, треугольник Voodoo, блок ATA, сектор FDC, синтез
EMU8000, презентация SDL) обёрнуты в `PerfScope`. CPU измеряется «фазой»
между двумя батчами; время устройств, вызванное гостевыми портами внутри
фазы, вычитается, поэтому узлы не считаются дважды. Фронтенд открывает и
закрывает кадр профилировщика на каждой итерации цикла, так что в панель
F3 попадают и хостовые этапы: загрузка текстуры, `SDL_RenderPresent` и сон
в бюджете 60 Гц. Подробности и ограничения — [perf.md](perf.md).

## Память

`Bus` хранит отсортированные регионы и разрешает пересечения в пользу более
позднего (более специфичного) региона. I/O-карта — массив из 65536 указателей
на `IoDevice`; 16/32-битные доступы идут в устройство только если весь
диапазон принадлежит ему, иначе собираются из байтов/слов. Это важно для
IDE data port, S3 `OUT DX,AX` и EMU8000, которые переопределяют
16/32-битные методы.

## Часы

`Machine` использует отдельную частоту планировщика (48 MHz для 233, 64 MHz
для 333), чтобы хост успевал исполнять инструкции. Это и есть реальная
скорость, которую видит гость: номинальные 233/333 МГц сохраняются только
для CPUID, TSC и документации. Частоту можно поднять или опустить опцией
`--sched MHz` (например, `--sched 32` — старые консервативные значения для
медленного хоста, `--sched 233` — «как паспорт», но хост на MDK за ним не
успеет и real time упадёт). PIT/RTC/S3/audio получают ту же частоту
планировщика, поэтому таймеры остаются пропорциональными эмулируемому
времени.

Быстрый путь доступа к памяти: `Bus` держит карту 64-килобайтных страниц;
страница, полностью занятая обычной RAM, читается/пишется напрямую через
`ram_base_`, без обхода регионов. Для VGA/ROM/MMIO остаётся бинарный поиск
по регионам с одноэлементным кэшем (типичный последовательный доступ к
кадровому буферу). `Cpu::translate` проверяет TLB прямо в заголовке, а
страничный обход вынесен в `translate_slow`. PIC сообщает CPU об изменении
линии INT, поэтому интерпретатор не вызывает `acknowledge()` на каждой
инструкции.
