# Отладка гостя и эмулятора

Для локализации багов в гостевом коде (DOS-extender'ы, установщики, игры)
у `oldbox` есть набор диагностических опций. Все адреса и селекторы задаются
в шестнадцатеричном виде без префикса `0x`.

Если нужно понять не *что* делает гость, а **почему эмулятор не успевает за
реальным временем**, используйте панель счётчиков производительности (F3) и
отчёт `--perf`/`perf`: они раскладывают хостовый кадр по аппаратным узлам.
См. [perf.md](perf.md).

```bat
oldbox.exe --bios assets\bios\EP-ZXA.bin ^
  --vga-bios assets\vga\S3Trio64_1_14-04.bin ^
  --floppy assets\floppy\freedos-win95.img ^
  --cdrom C:\Isos\Windows95OSR2.iso ^
  --hdd assets\hdd\win95-hdd.img ^
  --headless --seconds 60 ^
  --exc-trace ^
  --break 0387 ^
  --watch-phys 40de20:40e8e0 ^
  --dump-phys 0:fffff:low.bin ^
  --trace-cs 0387 --trace-file trace0387.txt
```

## Опции

| Опция | Назначение |
|---|---|
| `--exc-trace` | Печатает до 512 исключений: вектор, error code, `CS:IP`, opcode, CPL, режим, CR0, EFLAGS, регистры и все сегменты (селектор/base/limit/access/flags). |
| `--break CS[:IP]` | Останавливает эмуляцию и печатает полный снимок: регистры, сегменты, GDTR/IDTR/LDT/TR, PIC, кольцо последних 64 `CS:IP`, хвост трассы. Без `:IP` срабатывает на первом входе в селектор `CS` (удобно, чтобы поймать вход в гостевой модуль). |
| `--watch-phys LO:HI` | Логирует каждую запись в физический диапазон: `CS:IP`, размер, адрес, значение. До 200 000 строк. |
| `--dump-phys LO:HI:FILE` | Дамп физической памяти при срабатывании точки останова и при выходе. |
| `--trace-cs SEL` | Хранит трассу инструкций только одного селектора кода (8192 строк); в строке есть `DS`/`ES` и регистры. |
| `--trace-file FILE` | Записывает накопленную `--trace-cs` трассу при выходе. |
| `--instr-log FILE` | Полный лог инструкций (может быть очень большим). |
| `--dump-ram FILE` | Первый мегабайт гостевой RAM на выходе. |
| `--watch-start N` | Начинает логировать `--watch-phys` только после N эмулированных секунд (удобно пропустить тест памяти BIOS). |
| `--watch-cs SEL` | Логирует только записи, сделанные кодом с селектором `CS = SEL` (например, `--watch-cs 28d` — только HIMEM). |
| `--enter-every N`, `--enter-start N` | Сценарий автоустановки: жать Enter каждые N секунд, начиная с `--enter-start`. |
| `--dump-pcs`, `--dump-control` | Кольцо последних PC и история передач управления (call/jmp/iret/int). |

## Приёмы

- **Поймать вход в модуль.** `--break 0387` остановит на первой инструкции
  с этим селектором и покажет кольцо PC — откуда был переход.
- **Понять, кто портит память.** `--watch-phys` на диапазон: в логе видно
  `CS:IP` писателя и значение. Для A20-окон полезно смотреть и адрес с
  выключенной A20 (младший алиас).
- **Почему #GP.** `--exc-trace` показывает вектор, error code и точный
  `CS:IP`/opcode до того, как CPU изменит состояние. Для segment-load
  ошибок error code — это селектор.
- **Подозрение на неверную инструкцию.** `--trace-cs` + `--trace-file`
  дают окно в 8192 инструкций с регистрами и `DS`/`ES`; по нему видно,
  какая инструкция дала неверный результат.
- **Снять состояние гостя.** `--break` уже печатает сегменты и PC-кольцо;
  `--dump-phys` сохраняет физическую память для офлайн-дизассемблирования
  (`objdump -D -b binary -m i8086`).

## Ограничения

- Точки останова и трасса замедляют эмуляцию (на каждую инструкцию
  вызывается callback).
- `--trace-cs` хранит только последние 8192 инструкций; для длинных
  сценариев используйте несколько точек останова.
- Дамп физической памяти читает через Bus, поэтому не учитывает paging;
  при включённой страничной адресации это физические, а не линейные адреса.
