# YMF262 (OPL3): спецификация и реализация

Источники:

- [`specs/yamaha_ymf262.md`](../specs/yamaha_ymf262.md) — транскрипция
  даташита Yamaha YMF262 (OPL3, Catalog No. 4MF262A6, ноябрь 1994).
- [`src/opl3.hpp`](../src/opl3.hpp), [`src/opl3.cpp`](../src/opl3.cpp) —
  модель чипа.
- [`src/awe64.cpp`](../src/awe64.cpp) — включение OPL3 в звуковой тракт
  Sound Blaster AWE64.

## Что реализовано

Модель регистрового файла и звукового тракта YMF262:

| Возможность (даташит) | Реализация |
|---|---|
| Два массива регистров, A1 = L/H | `regs_[512]`, два независимых адресных защёлкивания `index_[2]` (порты 388h/389h и 38Ah/38Bh) |
| OPL2-совместимость (NEW = 0) | Только 9 каналов, 4 waveform, запись в массив 1 игнорируется, 4-оп режим выключен |
| OPL3 (NEW = 1, регистр 105h) | 18 каналов / 36 операторов, 8 waveform, массив 1 активен |
| 18 двухоператорных каналов | Каналы 1–9 в массиве 0, 10–18 в массиве 1 |
| 6 четырёхоператорных каналов | `CONNECTION SEL` (104h), пары каналов 1/4, 2/5, 3/6, 10/13, 11/14, 12/15 |
| Четыре схемы 4-оп соединения | FM-FM, AM-FM, FM-AM, AM-AM по битам CNT(Cn) и CNT(Cn+3); все четыре оператора используют частоту базового канала |
| Ритм-режим (BDh) | BD (слоты 13/16), SD (17), TOM (15), TC (18), HH (14); шумовой генератор и раздельные огибающие |
| 8 waveform (E0h–F5h) | sine, half-sine, absolute-sine, quarter-pulse, alternate sine, alternate absolute, square, falling sawtooth |
| MULT (20h–35h) | Таблица 1/2 … 15 из даташита |
| KSL (40h–55h) | ROM 16 значений + сдвиги 0/3/1.5/6 дБ на октаву, порядок колонок 0,2,1,3 |
| TL (40h–55h) | 0,75 дБ на шаг в 0,1875 дБ-единицах огибающей |
| AR/DR/SL/RR | 4-битные поля; внутренняя ставка `value*4 + Rof`, `rate 0` = без движения |
| SL = 15 | Полное затухание 93 дБ (тишина), как в даташите |
| NTS (08h) | Key scale = BLOCK*2 + F-number bit 8 (NTS=0) или bit 9 (NTS=1) |
| KSR | `Rof` из таблицы даташита (KSR=1 — номер ключа, KSR=0 — номер/4) |
| AM / VIB | 3,7 Гц tremolo и 6,1 Гц vibrato; DAM 1,0/4,8 дБ, DVB 7/14 центов |
| EGT | EGT=1 держит SL при KON=1; EGT=0 запускает release даже при KON=1 |
| FNUM/BLOCK | `f = FNUM * 49716 * 2^(BLOCK-20)`, умножение на MULT |
| KON | Key-on/off с сохранением фазы (без щелчка повторного запуска) |
| FB | 0 … 4π (0 … 2 периода) по таблице обратной связи |
| CHA–CHD (C0h D7–D4) | Четыре независимых выхода; A/C микшируются в левый, B/D — в правый канал |
| Timer 1 / Timer 2 | 80 мкс / 320 мкс, preset, ST1/ST2, MT1/MT2, RST, FT1/FT2/IRQ |
| Статус | D7 IRQ, D6 FT1, D5 FT2; маски подавляют только IRQ-бит |
| Reset | Все регистры и состояние очищаются, кроме выбранной частоты сэмплирования и тактовой частоты |

Огибающая ведётся в 9-битных единицах затухания (0 = максимум, 511 =
тишина), а не в линейной амплитуде. Это важно для OPL-характера: attack,
decay и release — линейные в дБ, а звук получается экспоненциальным по
амплитуде. Для скорости используются таблицы синуса (1024 точки с линейной
интерполяцией) и таблица затухания (512 значений), поэтому на сэмпл нет
`sin()`/`pow()` на каждый оператор.

## Отличия и осознанные упрощения

1. **Чтение статуса сбрасывает FT1/FT2/IRQ.** В даташите написано, что
   флаги сбрасываются только записью RST. Модель сохраняет
   read-to-clear-поведение, потому что на него рассчитывают AdLib-проба и
   DOS-драйверы (и это закреплено тестом
   `audio_opl3_status_read_clears_timer_flags`); запись RST также очищает
   флаги. Если нужна буквальная трактовка даташита, это одна из точек
   расхождения.
2. **Нет аналогового последовательного интерфейса DAC.** Даташит описывает
   DOAB/DOCD, φSY, SMPAC/SMPBD и 16-битный offset-поток для YAC512. В
   эмуляторе эти четыре канала сразу микшируются в стереопару; выбор
   CHA–CHD реализован, но тайминги сэмпл/холд не моделируются.
3. **Назначение A/C → левый, B/D → правый** — это вариант подключения
   YAC512 (пример 1/2 даташита различаются коммутацией sample/hold).
   Программно важны сами биты CHA–CHD, а не конкретная разводка платы.
4. **CSM (бит 7 регистра 08h) и LSI TEST (регистр 01h) игнорируются.**
   В карте регистров YMF262 они не описаны как функции; NTS (бит 6)
   реализован.
5. **Таймеры считаются от частоты планировщика CPU**, а не от отдельного
   генератора 14,32 МГц. Поскольку гостевые циклы привязаны к планировщику,
   80/320 мкс сохраняются в эмулируемом времени при любом `--sched`.
6. **Шумовой генератор** — свободно бегущий 23-битный LFSR (полином
   x^23 + x^18 + 1), один бит на сэмпл. Даташит не задаёт полином; важны
   шумовой характер и общий источник для SD/TC/HH.
7. **Точные времена огибающей** не приведены в даташите (только ставки).
   Модель использует калибровку OPL3: 0,2 мс attack и 50 мс «хвост 1 %»
   при внутренней ставке 60, шаг 2^(1/4) на единицу ставки. Attack
   считается по полному диапазону, decay/release — по 40 дБ (1 %), поэтому
   полный release 96 дБ занимает примерно в 2,4 раза больше.
8. **DVB «7/14 percent»** в даташите трактуется как 7/14 центов отклонения
   частоты — это стандартная глубина вибрато OPL3. Буквальные проценты
   (≈117 центов для 7 %) дали бы неправдоподобно широкое вибрато.

## Почему звук не «заикается»

До переработки звук синтезировался по одному сэмплу внутри
`Awe64::tick`, причём на каждый сэмпл заново считались шесть `pow()` для
микшера CT1745 и два `tanh()`; OPL3 на каждый оператор каждого сэмпла
вызывал `sin()` и `exp2()`. Это могло не успевать за аудиоустройством и
давать пропуски. Сейчас:

1. **Блочный синтез.** `Awe64::mix_internal` рендерит EMU8000 и OPL3
   блоками до 1024 сэмплов, затем применяет микшер и DSP DAC построчно.
2. **Кэш громкостей микшера.** `refresh_mixer_gains()` пересчитывает
   CT1745 только при записи в микшер, а не на каждом сэмпле.
3. **Без `tanh` на сэмпл.** Выход карты ограничивается аппаратным
   `clamp`; перегрузка и раньше была невозможна при штатных уровнях.
4. **Синтез по требованию.** `Awe64::render` заранее генерирует ровно
   столько внутренних 44,1 кГц-сэмплов, сколько нужно ресемплеру на
   запрошенный блок. Исчезли ветка «сгенерировать один сэмпл посреди
   ресемплера» и кольцевая логика `tick`, которая могла отбрасывать
   сэмплы при переполнении.
5. **Очередь SDL с запасом.** `push_audio` держит около трёх видеокадров
   (≈50 мс) в аудиопотоке и доливает его, если очередь опустела. Это
   поглощает джиттер планировщика и блокировку `SDL_RenderPresent`.
6. **Догоняющие кадры.** Главный цикл SDL выполняет до трёх гостевых
   кадров за итерацию, если хост отстал, и проталкивает аудио на каждый
   выполненный кадр. При паузе задолженность не накапливается.
7. **DMA идёт по эмулируемому времени.** Позиция DSP DMA, границы блоков
   и IRQ продвигаются в `Awe64::tick` (плюс кольцо DAC-сэмплов), а не по
   факту вызова `render`. Поэтому headless-прогон и верхнеуровневый
   аудиобуфер не рассинхронизируют DMA; если хост доливает буфер сверх
   эмулируемого времени, DAC отдаёт тишину, а не «перематывает» DMA.

Регрессионный тест `audio_opl3_sustained_note_does_not_stutter` гоняет
пять эмулируемых секунд непрерывной ноты через реальный тракт `Awe64`
(тик CPU + `render` по 735 сэмплов) и проверяет, что нет ни одного
«тихого» видеокадра и нет длинных нулевых провалов.

## Тесты

В [`tests/test_audio.cpp`](../tests/test_audio.cpp) добавлены проверки:

- `audio_opl3_register_arrays_have_independent_address_latches` — два
  адресных защёлкивания;
- `audio_opl3_opl2_mode_ignores_secondary_bank` — OPL2 не видит массив 1;
- `audio_opl3_waveform_select_is_implicit_in_opl3_mode` — 8 waveform
  работают без бита WSE;
- `audio_opl3_four_operator_connections` — все четыре схемы 4-оп;
- `audio_opl3_four_operator_key_on_is_base_only` — KON только базового
  канала;
- `audio_opl3_rhythm_has_all_five_sounds` — BD/SD/TOM/TC/HH;
- `audio_opl3_dac_channels_c_and_d` — выходы CHC/CHD;
- `audio_opl3_tremolo_modulates_amplitude`,
  `audio_opl3_vibrato_modulates_pitch` — LFO;
- `audio_opl3_total_level_is_0_75db_per_step` — TL;
- `audio_opl3_sustained_note_does_not_stutter` — отсутствие провалов;
- `audio_opl3_render_at_other_host_rates_does_not_drop_out` — ресемплинг
  на 22,05 и 48 кГц;
- `audio_dsp_dma_advances_from_tick_without_render` — DMA/IRQ идут по
  эмулируемому времени и без вызовов `render`.

Старые тесты (таймеры/статус, waveform, KSL, 4-оп, ритм, EGT) сохранены.
