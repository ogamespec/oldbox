# CMOS/NVRAM: хранение настроек между запусками

## Как это устроено в PIIX4

По даташиту `82371AB.PDF` (раздел 8.9) RTC содержит **256 байт
battery-backed SRAM** в двух банках по 128 байт. Банки не являются
окнами одного массива: у каждого своя пара index/data.

| Банк | Порты | Содержимое |
|---|---|---|
| Standard | `70h` (index), `71h` (data) | `00h–09h` — время, дата и alarm; `0Ah` REGA; `0Bh` REGB; `0Ch` REGC; `0Dh` REGD; `0Eh–7Fh` — 114 байт general-purpose RAM |
| Extended | `72h` (index), `73h` (data) | 128 байт general-purpose RAM |

Доступ к банкам разрешает `RTCCFG` — PCI-конфигурационный регистр
function 0, offset `CBh`, reset value `21h`:

- бит 0 — standard bank enable (`70h/71h`);
- бит 2 — extended bank enable (`72h/73h`), по умолчанию **выключен**;
- биты 3/4 — lock для байтов `38h–3Fh` соответственно standard/extended
  банка; после установки снимаются только hardware reset (PCIRST#);
- бит 5 — positive decode RTC I/O.

Питание RTC идёт от батареи, поэтому 256 байт сохраняются, когда машина
выключена. `RTCCFG` — обычный регистр чипсета, а не battery-backed: при
сбросе он возвращается к `21h`, а lock-биты снимаются.

## Что делает oldbox

`Rtc` моделирует оба банка, порты `70h–73h`, `RTCCFG` и lock-биты.
Поверх этого `oldbox` хранит сырой образ 256 байт в
`assets/cmos/cmos.bin` (standard bank, затем extended).

- При старте, **после** `Machine::reset()`, образ загружается в RTC. Поэтому
  `Save & Exit Setup` из прошлого запуска виден BIOS как обычные сохранённые
  настройки, а не как fresh defaults.
- При штатном выходе (закрытие окна, конец `--seconds`, выход из SDL)
  текущие 256 байт записываются обратно. Каталог создаётся автоматически.
- В образ попадают и часы: при следующем запуске RTC продолжает с
  сохранённого момента. Оффлайн-время (сколько эмулятор был выключен) не
  добавляется — эмулятор не привязан к host clock.
- Время восстанавливается, если образ в BCD/24h (BIOS default, `REGB=02h`).
  Если гость переключил RTC в binary/12h, конфигурация всё равно
  восстанавливается, а часы остаются на reset-значении.
- Award-контрольная сумма `2E/2F` — часть образа; при загрузке она не
  пересчитывается. `cmos set` в консоли пересчитывает её, как и BIOS.
- `RTCCFG` и lock-биты не сохраняются: они не battery-backed и сбрасываются
  в `21h` при старте/PCIRST.

## Файл и опции

```text
assets/cmos/cmos.bin     256 байт: standard bank 00h–7Fh, extended 00h–7Fh
```

| Опция | Действие |
|---|---|
| `--cmos-image FILE` | другой файл NVRAM (по умолчанию `assets/cmos/cmos.bin`) |
| `--no-cmos-image` | не читать и не писать образ (детерминированные прогоны) |
| `--cmos FILE` | разово загрузить 128-байтовый CMOS-дамп до POST; образ всё равно сохраняется на выходе |

Образ читается и как 128-байтовый legacy-дамп: standard bank
восстанавливается, extended заполняется `FFh`. Файл можно смотреть любым
hex-редактором; формат не содержит заголовка.

`assets/cmos/` исключён из git: это пользовательские настройки конкретной
машины, а не часть репозитория. Для чистого старта удалите
`assets/cmos/cmos.bin` или запустите с `--no-cmos-image`.

## Диск C: и «Save & Exit Setup»

Параметры primary master Award 4.51PG хранит не в чипсете, а в CMOS:

| CMOS | Значение |
|---|---|
| `12h` | `F0h` — primary master есть (тип auto), slave отсутствует |
| `19h` | `2Eh` — запись user/auto типа |
| `26h–27h` | число цилиндров (word) |
| `28h` | число головок |
| `29h–2Ah` | write precomp (word, `FFFFh` — нет) |
| `2Bh–2Ch` | landing zone (word) |
| `2Dh` | секторов на дорожку |
| `79h`, `7Eh` | бит 4 — LBA-трансляция |

`Machine::reset()` заполняет этот блок из реально подключённого primary
master до запуска BIOS. После этого Setup видит диск, а `Save & Exit`
записывает те же параметры обратно; `hard_reset()` их не стирает, поэтому
C: не отваливается. Загруженный `assets/cmos/cmos.bin` применяется **после**
reset и перекрывает авто-геометрию — то есть сохраняются настройки
пользователя, а не заново вычисленные.

Если образ CMOS был создан старой версией (с нулевым блоком `26h–2Dh`),
`ensure_primary_master_cmos()` при старте заполнит его из подключённого
primary master: непустая пользовательская геометрия при этом не трогается.
При замене образа HDD на другой с другой геометрией обновите настройки
через `IDE HDD AUTO DETECTION` или удалите `assets/cmos/cmos.bin`.
